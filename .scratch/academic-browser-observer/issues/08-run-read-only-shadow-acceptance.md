# 08: Run an authorized real-system read-only Shadow acceptance

**What to build:** With the user's explicit authorization and established visible browser session, observe one manually performed read-only academic query without controlling the page. Independently verify that topology, request candidates, redaction, completeness, and borrowed detach match reality, then record the strongest supported evidence tier and unresolved risks.

**Blocked by:** 07/Prove observer value with historical and hidden evals

**Status:** ready-for-human

- [ ] The user identifies and authorizes one specific read-only operation before observation starts.
- [ ] The observer only connects, inventories, starts observation, checkpoints or stops, and disconnects; it does not click, fill, navigate, evaluate arbitrary JavaScript, or submit.
- [ ] Local human DevTools observation independently confirms the relevant target, redirects, and candidate request shape without copying raw evidence into the repository or model context.
- [ ] No credential, cookie, token, student record, full response, raw HTML, screenshot, or unredacted URL is persisted or shown to the model.
- [ ] Disconnect leaves the user's browser, profile, session, and existing tabs alive.
- [ ] Any missing target, incomplete trace, semantic contradiction, or redaction uncertainty records a failed or partial acceptance rather than a pass.
- [ ] The acceptance report distinguishes implemented, automated-test verified, and real-environment verified capabilities.
- [ ] The report states whether the observer removed at least one manual DevTools step and records remaining manual interventions and release risks.
