# 02: 定位并只读探索对应教务选课入口

**What to build:** 用户选择一个已确认的选课窗口后，工具通过现有可视浏览器会话进入对应教务菜单，确认匹配的选课轮次，并只读呈现能够获得的课程班、教师、时间、容量和已选状态。工具优先识别页面实际使用的网络接口，为后续稳定读取建立经过脱敏的请求契约。

**Blocked by:** 01/导入并确认选课通知.

**Status:** ready-for-agent

- [x] 能区分登录失效、入口不可达、轮次未开放、无匹配轮次和真实空结果。
- [x] 探索期间不发送选课、退课、保存或提交请求，也不点击会改变选课状态的控件。
- [x] 记录接口方法、参数形状和响应字段时移除 Cookie、令牌、学号、姓名及其他身份信息。
- [ ] 稳定读取优先使用与浏览器共享认证状态的请求上下文；接口不可确认时保持只读并报告阻塞，不猜测提交契约。
- [x] 通过固定响应样本验证课程班字段解析和数据不完整状态。

## Comments

已实现只读探索命令：认证后由用户手动打开对应学生选课页面，程序只接收匹配通知文本的标签页，监听 Fetch/XHR，保存课程班结果和脱敏请求契约，并在本地页面呈现状态。未捕获到可确认接口时报告 `interface_unconfirmed`，不会误报为空；稳定接口的 `browser_context.request` 直读仍需在真实选课窗口捕获并确认请求契约后实现，当前不会猜测或重放提交请求。
