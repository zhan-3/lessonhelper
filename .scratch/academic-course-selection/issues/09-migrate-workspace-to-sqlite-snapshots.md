# 09: 将现有工作区迁移为 SQLite 快照

**What to build:** 学生升级并启动工作台时，现有学生画像、已确认通知、当前课表和只读待选结果被安全导入本地 SQLite，之后页面从唯一的结构化事实来源读取数据。迁移失败不会破坏原工作区，也不会产生同时写 JSON 和数据库的分叉状态。

**Blocked by:** 08/收紧并抽出只读教务网关.

**Status:** ready-for-agent

- [ ] 空工作区首次启动会创建带版本记录的本地数据库，并启用外键、WAL 和有限 busy timeout。
- [ ] 支持的现有画像、通知、课表和待选 JSON 在首次启动时只导入一次，导入后页面呈现的领域事实不丢失。
- [ ] 旧 JSON 文件作为只读迁移证据保留，后续状态变化只写 SQLite，不进行双写。
- [ ] 快照元数据、课表条目、待选课程班、通知版本、画像版本和刷新尝试具有可查询的结构化关系。
- [ ] 数据库升级前创建本地备份，编号迁移在事务中执行；任一迁移失败会完整回滚并阻止工作台使用半升级数据库。
- [ ] 密码、Cookie、令牌、学号、姓名和原始 HTML 不进入数据库。
- [ ] 临时数据库上的迁移和回滚测试验证空安装、重复启动、旧 JSON 导入及失败恢复。
