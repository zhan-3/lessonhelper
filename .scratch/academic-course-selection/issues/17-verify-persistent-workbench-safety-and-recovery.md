# 17: 完成常驻工作台安全与现场验收

**What to build:** 学生获得一个可以长期本地运行、出错后仍能理解和恢复的完整只读工作台。发布前通过自动安全测试和一次真实连续刷新验证，证明服务只使用一个浏览器、不会在测试中途关闭，也不会发送选课写请求。

**Blocked by:** 13/刷新完整待选课程快照; 14/刷新真实课表快照; 15/发现并确认官方选课时间通知; 16/叠加候选课程并形成只读选课规划.

**Status:** ready-for-agent

- [ ] 正式模式通过一个命令启动 Flask API、任务管理器和 React 构建产物，服务只绑定 loopback，第二次启动复用现有工作台。
- [ ] 本地状态变更 API 通过同源与 CSRF 检查，观察任务在导航、请求和重试层均阻断已知及疑似选课写操作。
- [ ] 浏览器关闭、认证超时、任务取消、网络失败和服务重启均保留最近完整快照，并给出可操作状态而不是空白页面。
- [ ] 快照保留策略删除超出最近二十份的结构化历史，同时确认 SQLite、日志和诊断中没有原始 HTML、凭据、Cookie、令牌、学号或姓名。
- [ ] 自动验收从 Flask JSON API 经过应用服务、任务队列和临时 SQLite，使用确定性假网关验证主要用户流程而不依赖内部线程或 SQL 实现细节。
- [ ] 前端关键流程验证连接状态、任务进度、旧快照警告、周/日课表、候选叠加和只读规划。
- [ ] 真实现场验收在同一常驻 Chromium 中依次刷新课表、刷新全部白名单课程并再次刷新；期间不重复启动浏览器，服务端未主动失效时不重复认证。
- [ ] 现场审计确认所有分页完整或正确保留旧快照，且网络记录中没有选课、退课、保存或注册请求。
