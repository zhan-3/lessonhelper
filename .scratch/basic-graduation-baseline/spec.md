# 基础毕业要求基线 v1

Status: resolved

## Problem Statement

原选课规划工作台的主体只读功能已由用户报告验收通过；当前阶段不再扩展浏览器观察工具，也不在选课窗口尚未开放时推进真实抢课。阶段收尾的重点是使学分进度能够依据一版明确的基础毕业要求，解释已确认完成、预计完成及仍无法确认的条件。

现有进度主要按课程类别累加学分，无法完整表达 D 类、四史、创新创业与社会实践组合要求以及外专业课程体系约束。部分规则写在前端，部分来自指南解析；进度面板又受待选课程查询类别过滤，导致社会实践等要求可能不显示。仅有总学分可能被误解为满足整个要求。

成绩记录不能覆盖所有认定学分。学生需要在本地补充申报，但手工输入不能被当作教务系统确认。历史报告也不能在切换规则后被静默重新解释。

## Solution

提供一个由用户主动选择、不可原地修改的参考版本 `basic-graduation-reference-v1`。版本覆盖本阶段约定的选修及认定学分最低要求，不包含完整专业培养方案和学校正式毕业审核。

全部要求固定展示，与待选课程查询范围无关。每项区分已确认完成、本学期已选、队列预览、用户申报、预计缺口和待核验项。计算结果使用已满足、未满足、未知三态；只在已确认事实足以证明全部必要条件时显示已满足。用户申报只能影响预计完成。

基础规则如下：

| 要求 | 本版参考值 | 必要说明 |
| --- | --- | --- |
| 本专业选修 | 至少 3 学分 | 来自现有提纯指南，不宣称所有专业统一适用 |
| 创新创业 | 至少 4 学分 | 来自用户提供的参考图，作为人工补充规则；不是已核实的全校统一规定 |
| 社会实践 | 至少 1 学分 | 同时贡献于组合要求 |
| 创新创业 + 社会实践 | 合计至少 6 学分 | 合计与两个单项条件都需满足，4 + 1 仍缺 1 学分 |
| 文化素质 | 至少 8 学分 | 包含下列子约束贡献，不在总额之外重复追加 |
| 文化素质 D 类 | 至少 2 学分 | 需要明确类别依据 |
| 四史 | 至少 1 门已完成课程 | 按课程身份去重；不是统一规定为 2 学分 |
| 外专业/跨专业 | 至少 10 学分 | 需在一个选定课程体系内完成，不能跨体系任意拼总额 |

本版为固定参考选择，不自动匹配所有年级。已知年级或专业差异以适用性提示呈现，不在前端偷偷改写阈值；其他正式规则由后续独立版本承载。

## User Stories

1. As a 学生, I want 主动选择基础毕业要求基线, so that 我知道当前进度采用哪套参考规则。
2. As a 学生, I want 查看基线版本和来源说明, so that 我不会把个人参考图误当作学校正式培养方案。
3. As a 学生, I want 在选用前看到覆盖范围与非正式性质, so that 我知道专业必修和完整毕业审核不在本版范围内。
4. As a 学生, I want 基线不因年级推导而被自动切换, so that 已选择的计算口径保持稳定。
5. As a 学生, I want 查看本专业选修的最低要求与进度, so that 我能规划尚需完成的课程。
6. As a 学生, I want 分别查看创新创业和社会实践, so that 单项不足不会被合计掩盖。
7. As a 学生, I want 查看创新创业与社会实践的合计条件, so that 我不会把 4 加 1 误认为满足至少 6 的要求。
8. As a 学生, I want 看到创新创业 4 学分属于人工补充参考规则, so that 我能对照个人培养方案核对。
9. As a 学生, I want 同时查看文化素质总额与 D 类要求, so that 总额足够时也不会漏掉必要子约束。
10. As a 学生, I want 单独查看四史课程门数, so that 门数条件不会被学分总量替代。
11. As a 学生, I want 同一门四史课程跨学期出现时只计一门, so that 重复记录不会夸大进度。
12. As a 学生, I want 外专业进度按选定课程体系核对, so that 不同体系的课程不会被错误合并成达标。
13. As a 学生, I want 明确的体系映射保留证据来源, so that 我能理解某门课程为何计入一个体系。
14. As a 学生, I want 缺乏体系或课程标签时显示未知, so that 缺少数据不会伪装成已满足或零完成。
15. As a 学生, I want 全部基线要求始终展示, so that 待选课程只查询某些类别时不会隐藏毕业要求。
16. As a 学生, I want 分开查看已确认完成与预计完成, so that 在修或未确认记录不会被当作已经取得的学分。
17. As a 学生, I want 本学期已选课程独立展示, so that 我知道哪些预计贡献来自当前修读课程。
18. As a 学生, I want 队列预览课程独立展示, so that 我知道尚未选中的课程只是一种规划假设。
19. As a 学生, I want 预览课程不重复计算已完成或本学期已选的同一课程, so that 预计学分不被夸大。
20. As a 学生, I want 在本地录入认定学分的类别、学分、说明和日期, so that 成绩接口未覆盖的活动可以参与个人规划。
21. As a 学生, I want 修改和删除自己的申报, so that 录入错误可以纠正。
22. As a 学生, I want 用户申报始终带有未核实标识, so that 手工输入不会伪装成学校确认。
23. As a 学生, I want 用户申报只参与预计完成, so that 它不会提高已确认完成量。
24. As a 学生, I want 为无法归类的课程补充 D 类、四史或课程体系标签, so that 我可以形成个人参考估值。
25. As a 学生, I want 手动标签不覆盖教务原始字段, so that 后续核对能区分学校事实和个人判断。
26. As a 学生, I want 手动标签带来的子约束贡献只算预计, so that 我的判断不会使原本未知的已确认条件直接达标。
27. As a 学生, I want 看到每项学分及门数贡献的来源, so that 我能检查重复、误分类和不适用记录。
28. As a 学生, I want 同一课程在总额中仅计一次但可同时贡献必要子约束, so that D 类或四史不会增加一份重复的文化素质总学分。
29. As a 学生, I want 申报与课程事实重叠时被明确处理, so that 同一学分不会同时算作课程学分和认定学分。
30. As a 学生, I want 查看已确认缺口和计入预计贡献后的缺口, so that 我能区分确定事实与个人计划。
31. As a 学生, I want 无法确认的条件显示未知及原因, so that 我知道下一步需要核验什么。
32. As a 学生, I want 总额足够但子约束未知时不显示整个要求已满足, so that 工作台不会给出误导性的完成提示。
33. As a 学生, I want 切换新基线时旧报告保留为历史, so that 我可以核对原有计算结果。
34. As a 学生, I want 新基线要求显式重新同步后生成新报告, so that 旧报告不会被静默重新解释。
35. As a 学生, I want 同步失败时保留旧完整快照并说明新报告尚不可用, so that 失败不会变成空进度或零学分。
36. As a 学生, I want 本地切换基线、编辑申报和查看历史不访问学校系统, so that 我掌握远程访问时机。
37. As a 学生, I want 重启后恢复基线选择和申报, so that 我不必重复填写。
38. As a 学生, I want 清除个人工作区时一并清除申报和个人标签, so that 更换账号不会继承另一个人的进度。
39. As a 学生, I want 页面明确说明结果不是学校毕业审核结论, so that 我不会据此作出正式毕业资格判断。
40. As a 维护者, I want 基线与类别映射共同版本化, so that 规则变化不会悄悄影响历史计算。
41. As a 维护者, I want 后端统一计算规则和贡献, so that 前端不会另有一套阈值及归类算法。
42. As a 维护者, I want 使用现有读取和快照路径, so that 学分完善不会破坏已验收的工作台功能。
43. As a 维护者, I want 以模拟读取验证完整工作台流程, so that 无需在真实选课窗口执行操作即可完成开发回归。
44. As a 维护者, I want 将本阶段交付与待开放选课窗口分开记录, so that 抢课暂缓不会阻塞基础学分版本收尾。

## Implementation Decisions

- 复用现有要求基线、课程进度计算、工作台应用服务、SQLite 持久化、任务刷新及 React 展示边界。不新建第二条教务采集路径，不使用派生 Observer 的候选请求作为学分事实来源。
- 新增固定版本 `basic-graduation-reference-v1`，保留 `guide-2026`。规则数值、类别映射、子约束、来源及适用性说明作为同一不可变版本维护。不提供用户规则编辑器。
- 来源记录采用可共享的文字摘要和现有指南引用；用户提供的“哈威观察者”参考图注明为非官方参考。不得将个人图片绝对路径当作其他使用者可访问的规则来源，不自动公开原图。创新创业单项 4 学分的来源争议必须保留。
- 基线选择是本地个人工作区状态，需显式确认选择；安装或升级不能静默替用户选择新版本。无需建设通用多版本管理平台，只提供现有版本与新增参考版本所需的选择和历史标识。
- 新版报告必须绑定基线版本和可用的个人工作区上下文。不能仅以年级作为学生身份；兼容现有画像回退行为时也必须隔离个人申报，账号重置应清除个人数据。此功能不扩展为多账号管理。
- 选择新版后保留旧报告并标为历史，呈现“需要重新同步/计算”。选择本身不触发远程访问。首次新版报告必须由显式同步成功后产生；读取失败时不发布新报告，不把旧报告伪装为新基线报告。
- 已经取得适用新版数据之后，用户申报、手动标签和预览变化可以本地重算展示，不需要再次远程读取，也不改写学校来源快照。历史快照中的原报告保持不变。
- 沿用现有完整成绩分页读取、个人课表与本学期已选读取、通知及待选课程读取契约。不要为 D 类、四史或课程体系缺失字段增加未经验证的接口或菜单探索。
- 统一计算层输出最低要求、已确认完成、各类预计贡献、缺口、条件状态及原因、来源可追溯的贡献明细。前端消费结果而非维护另一套硬编码阈值；队列预览的计算应复用同一规则口径，通过既有本地规划/应用服务边界衔接，不引入新的远程能力。
- 课程身份优先使用课程代码，无代码采用既有规范化名称回退。已通过记录去重；事实冲突不计为已确认贡献。未知类别保留待归类，不能凭名称关键词认定 D 类、四史或体系。
- 基线内明确映射可以参与已确认条件判断。用户手动补充的分类、标签和体系选择是单独的申报覆盖层，不写回学校事实，也不自动晋升为权威映射。
- 已确认总学分中的一门课程，在用户手动标记 D 类或四史后，总学分不变；仅对应子约束的预计贡献变化。已通过课程不因标签申报再次增加总学分。
- 认定学分申报保存稳定记录身份、类别、正数有限学分、说明和日期，支持新增、修改、删除。拒绝负数、零、非有限数、非法日期及不支持的类别。与现有学分精度兼容，避免浮点边界导致阈值误判。
- 申报可关联已有课程或贡献以声明同一事项，已关联事实优先、总额不重复；重复关联不得重复贡献。对无稳定身份可证明的相似自由文本记录，不猜测为不同或相同事项；提示用户核对，不以模糊名称自动合并。首次创建后重复请求不能生成重复申报记录。
- 不支持将任意手填学分直接作为四史门数证明。四史预计门数来自绑定课程身份的手动标签或明确课程映射；无已完成记录的课程只提供预计贡献。
- 外专业要求按一个选定体系评估。明确属于其他体系的课程不计入该体系达标量；体系不明的课程保留可见并形成待核验项。用户声明的体系归属只参与预计条件判断。
- 每条事实在同一要求总额中最多计一次，可贡献其子约束和父级合计。创新与社会实践在组合要求中合并去重，不能将两个子项与组合项再次相加。
- 预计贡献区分本学期已选、队列预览、用户申报。相同课程的贡献优先级为已确认完成高于本学期已选、高于队列预览；手工补充不能为同一课程再次增加学分。认定事项没有可靠重叠身份时显示其申报性质和重复核验提示。
- 三态基于证据而非仅比较数值：可确认全部必要条件达到时为已满足；证据足以证明某必要条件未达到时为未满足；缺少覆盖或分类、无法判断时为未知。若组合存在明确未满足条件，则整体未满足，同时保留其他未知条件；没有明确未满足但有未知，则整体未知。
- 用户申报不消除已确认数据覆盖缺口、不提高已确认完成，也不能凭预计贡献将已确认状态改为已满足。预计可满足的提示必须显式注明为估算。
- 有数据覆盖缺口时，可以显示“距最低要求尚未被已确认事实覆盖的差额”，但不得将其描述为确定尚需取得的学分；预计缺口也不证明正式完成。无需给完整培养方案输出总毕业通过状态。
- 数据覆盖区分成绩读取完整与所有认定来源完整。完整读取所有成绩分页，不等于活动认定、课程体系和子约束来源全部覆盖。
- 用 SQLite 事务保存新本地状态及迁移，避免并行 JSON 写入。迁移保留现有画像、凭据、通知、学校快照、规划和任务；不得为此功能清理历史任务或重写无关 Observer 修改。
- 本地写 API 沿用同源与 CSRF 防护，响应和日志不增加账号、密码、Cookie、原始成绩、证书或原始页面。申报属于本地个人数据，仅存于已忽略的私有工作区。
- 页面固定展示全部基线要求；详细贡献可按需展开，合计和子约束明确关联。保留既有已确认、本学期已选、队列预览的区分，增加申报与未知说明，不对整个工作台进行视觉重设计。
- 同步后申报仍保留，并重新核对与新增学校事实的重复贡献；清除个人工作区时清除基线选择、申报和手动标签，公共基线定义及官方通知按现有约定保留。

## Testing Decisions

- 用户已确认以现有工作台 HTTP API 为主验收入口，临时 SQLite 加模拟教务读取。优先跨完整公开行为验证，不通过私有方法补丁或浏览器内部实现测试业务规则。
- 主链路测试覆盖：升级旧工作区、显式选择新版、旧快照历史展示、选择不访问学校、显式同步成功产生新版、刷新失败保留历史、新版就绪后本地申报重算、重启恢复及个人工作区重置。
- 复用现有工作台路由和应用服务测试中临时数据库、模拟 gateway、异步任务检查与完整快照发布的先例。新接口只补充薄适配器契约测试，不复制计算规则测试。
- 计算器作为辅助测试入口，表驱动覆盖每个最低值的低于、等于、高于边界；4 创新 + 1 社会实践不能满足合计 6；创新不足但合计足够仍未满足。
- 覆盖文化素质总量足够但 D 类不足、四史缺失或未知；一门课程同时属于 D 类和四史时可贡献两个子约束但总学分只计算一次；四史跨学期重复不增加门数。
- 覆盖外专业不同体系不能拼总额、未选择或未知体系、明确映射与手工标签的确认等级差异。
- 覆盖已完成、本学期已选、队列预览和申报之间的重复身份；冲突事实、未知类别、必修排除的既有规则保持不变。无法确证的重叠不得静默计为已确认贡献。
- 验证手动标签不改变已确认总学分、不会把已确认子约束从未知直接改成满足。用户申报只能影响预计结果；编辑和删除后立即撤销对应预计贡献。
- 验证完整成绩读取仍能留下认定来源覆盖缺口，未知不等于零；来源不完整时不得输出无条件整体已满足。
- 验证申报字段校验、稳定身份、重复请求幂等、重启持久化、重置隔离、CSRF/同源保护，以及异常事务不会产生半份申报或破坏旧快照。
- 前端采用公开用户交互测试：基线选择与范围提示、全部要求不受待选类别过滤、创建/修改/删除申报、手动课程标签、确认与预计分离、历史等待同步和未知原因显示。现有前端只有计算辅助测试的覆盖不替代新增交互测试。
- 前端学分及贡献计算沿用现有课表辅助测试的已完成/已选/预览去重先例，但测试应验证统一计算后的界面行为，避免对组件内部状态或 CSS 结构作断言。
- 本阶段完成需通过相关 Python 回归、前端计算及交互测试、类型检查、构建和静态检查；测试使用合成课程与申报，不复制真实学生记录到 fixture。
- 全量回归须单独列出进入本阶段前已有的 Observer 契约失败；不得将基线已有失败说成本功能通过，也不得无关修改掩盖失败。阶段交付报告明确已通过范围和未解决的无关失败，发布全绿要求不能靠忽略测试达成。
- 用户此前对工作台主体只读功能的现场验收作为“用户报告已验收”的证据保留，不虚构日期、运行记录或新增学分功能的现场验收。新学分规则和展示需独立人工核对，自动测试不升级为学校官方毕业结论。
- 真实选课窗口未开放，不发送任何选课或预约请求，不以执行链路现场验收作为本阶段学分功能的完成前提。

## Out of Scope

- 专业必修、专业总毕业学分、所有学院和年级的完整培养方案审核。
- 综合测评、保研资格、优秀加分及排名计算。
- 讲座场次、志愿时长、竞赛等级、论文、专利、项目等复杂换算和来源封顶引擎；第一版只接受用户直接申报参考学分。
- 证明材料上传、图片识别、证书真实性校验或将申报自动认定为学校确认。
- 用户编辑最低学分、通用规则 DSL、规则管理后台或自动同步学校政策。
- 根据课程名关键词猜测 D 类、四史或外专业体系。
- 新教务接口探索、Browser Observer 价值评估、CDP 拓扑开发、会话框架重写。
- 抢课、批量提交、自动重试、真实选课及实验预约验收。
- 为本功能顺便清理大量历史任务、重构启动流程、多账号支持或整体 UI 重设计。
- 删除旧快照、无提示切换基线、将历史报告原地修改成新版本。

## Further Notes

- 本 spec 来自用户确认的两轮默认决策，以及对测试入口的明确确认，不需要额外需求访谈或 triage。
- 用户明确表示原工作台其他功能已验收；本阶段仅补全基础毕业参考学分并收尾，选课提交因窗口未开放暂停。
- 用户选择本参考基线不意味着截图中的规则适用于所有年级、专业。尤其创新创业单项 4 学分与年级特殊规则须保留来源和适用性声明。
- 本专业选修 3 学分来自现有指南，而非参考图的单独条目；本版包含它是已确认范围，不得描述为从图中直接识别的规则。
- 该阶段完成可以表述为基础毕业参考基线已实现、自动测试验证及新增界面人工核对情况；不可表述为完整毕业审核或真实抢课已经通过。
- 既有 ADR 关于数据本地化、基线与映射共同版本化、Flask 薄适配器、SQLite 单一事实来源、React 前端、个人课表事实及固定读取契约继续适用。
- 下一阶段按本 spec 拆分贯穿计算、存储、API 和展示的纵向实施任务；本 spec 不授权立即执行真实学校写操作，也不要求提交或推送当前未提交修改。
