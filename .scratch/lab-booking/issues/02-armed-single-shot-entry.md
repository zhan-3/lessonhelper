# 02: 预先武装的一次性进入与提交

**Status:** ready-for-agent

## 目标

到开放时刻为止，用户只需按一次；工具自动完成"进入中心应用 → 提交已确认的目标"，
每门实验只提交一次，并记录可核对的类型化结果。

## 已实测的进入链

```text
POST /lmsAuthApi/apps/goto/{center}        → result.token（一次性证书）
POST /{center}/StuApi/auth/cas/login       → body vcToken，返回应用令牌
每个后续请求带请求头 vctchauthorization
```

失败的两种已知形态：`5000 当前用户未授权`、`应用已关闭, 请联系管理员`。

## 需求

- [ ] 支持"武装"阶段：本地保存待提交目标 + 确认令牌，不在武装时发起写请求。
- [ ] 支持"触发"阶段：到点执行进入 + 对每个目标提交一次；记录 `{code,message,result}`。
- [ ] 触发阶段必须是**单轮**：不轮询、不重试、不并发轰炸；一次触发只尝试一次。
- [ ] 结果不明（超时/非 JSON）标记 `possibly_applied` 并停止，等待人工核对。
- [ ] 进入失败（未授权 / 应用已关闭）时给出明确分类，不继续提交。
- [ ] 令牌只在内存中使用，不落盘；武装文件只含目标与令牌哈希。

## 边界

不做：绕过开放窗口或资格名单、伪造参数或身份、代他人操作、自动重试、循环抢位。
